# API Documentation

This section showcases my approach to documenting REST APIs for developers.

The examples are based on the fictional AcmePay cloud-native payments platform created as a self-directed portfolio project.

## API Documentation Coverage

### Getting Started

A practical introduction to connecting to an API, authenticating requests, sending requests, understanding responses, and troubleshooting common errors.

[Read the Getting Started Guide](projects/acmepay/getting-started.md)

### Authentication

Documentation covering API keys, Bearer tokens, OAuth 2.0, authentication errors, and API key security.

[Read the Authentication Guide](projects/acmepay/authentication.md)

### Payments API

Reference documentation for creating and retrieving payments, including request parameters, responses, payment statuses, idempotency, and common errors.

[Read the Payments API documentation](projects/acmepay/payments.md)

### Webhooks

Documentation explaining payment events, webhook payloads, event handling, duplicate events, signatures, retries, and security considerations.

[Read the Webhooks documentation](projects/acmepay/webhooks.md)

### API Reference

An OpenAPI-based API reference covering available endpoints, authentication, request schemas, response schemas, and HTTP errors.

[View the API Reference](projects/acmepay/api-reference.md)

[View the OpenAPI Specification](projects/acmepay/openapi.yaml)

[View the Interactive Swagger Reference](projects/acmepay/swagger.html)

### API Errors

A troubleshooting guide covering common HTTP errors and practical steps for diagnosing failed API requests.

[Read the API Error Guide](projects/acmepay/api-errors.md)
